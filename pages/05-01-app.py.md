# `app.py` 코드 해설집

## 한 문장으로 설명

`app.py`는 학생이 보는 웹 화면을 만들고, 문제를 출제·채점한 뒤 검색 근거와 MediKo 모델을 연결하는 **학교 축제의 진행 본부** 같은 파일입니다.

## 전문용어를 학교생활 말로 바꾸기

| 전문용어 | 쉬운 뜻 | 학교생활 비유 |
|---|---|---|
| Gradio UI | Python으로 만든 웹 화면 | 교실의 전자칠판과 버튼 |
| 환경변수 | 실행할 때 바꿀 수 있는 설정값 | 시간표에 적힌 교실·교시 |
| 지연 로딩 | 필요할 때 처음 불러오기 | 필요한 교과서만 사물함에서 꺼내기 |
| 캐시 | 한 번 구한 값을 다시 사용 | 자주 보는 공식을 포스트잇에 적기 |
| 가드레일 | 위험하거나 근거 없는 출력을 막는 검사 | 복도 안전 난간과 선생님의 확인 |
| 프롬프트 | 생성 모델에게 주는 지시문 | 수행평가 문제지의 작성 규칙 |
| State | 화면이 기억하는 현재 값 | 학생이 고른 답을 임시 메모지에 기록 |

## 코드 전체 맥락

1. `.env`에서 토큰, 모델, RAG 경로와 서버 주소를 읽습니다.
2. 직종별 KorMedMCQA 데이터셋을 필요할 때 한 번만 내려받습니다.
3. 학생이 직종과 연도를 고르면 무작위 문제를 표시합니다.
4. 정답 번호는 Python이 즉시 비교합니다. 이때 생성 모델은 실행하지 않습니다.
5. 학생이 해설을 요청하면 `문제 + 정답 보기`를 `local_rag.py`에 전달합니다.
6. 검색 근거가 충분한지 검사한 뒤 MediKo로 해설을 생성합니다.
7. 생성 결과가 근거 밖의 수치·가짜 출처·진료 지시를 포함하는지 다시 검사합니다.
8. 해설, 참고 근거, 안전 고지를 화면에 표시합니다.

## 코드 구역별 해설

### 1. 시작 설정과 네트워크: 1~98행

- `load_dotenv()`는 `app.py` 옆의 `.env`를 읽습니다.
- `JOBS`는 화면의 한글 직종을 데이터셋 이름으로 바꾸는 사전입니다.
- `app_server_settings()`는 `APP_HOST`, `APP_PORT`가 올바른지 검사합니다.
- `lan_access_urls()`는 같은 Wi-Fi 휴대폰이 접속할 노트북 IP를 찾습니다.

### 2. 문제 데이터 준비: 101~145행

- `get_dataset()`은 직종별 데이터를 Hugging Face에서 받습니다.
- `@lru_cache(maxsize=4)` 덕분에 같은 직종을 다시 눌러도 재다운로드하지 않습니다.
- `questions_by_year()`는 train·dev·test 문항을 연도별 서랍처럼 나눕니다.
- `random_question()`은 선택한 서랍에서 한 문제를 뽑습니다.

### 3. 해설 모델 준비: 148~211행

- `get_explainer()`는 첫 해설 요청 때만 모델을 불러옵니다.
- GPU가 있으면 `float16`, CPU이면 `float32`를 사용합니다.
- `MEDICAL_LORA_ADAPTER`가 비어 있으면 LoRA를 연결하지 않습니다.
- `fit_prompt_to_model()`은 모델의 입력 칸을 넘지 않게 검색 근거를 자릅니다.
- `apply_chat_template()`은 모델이 학습한 대화 형식에 지시문을 맞춥니다.

### 4. 안전 검사: 214~341행

- `invalid_explanation()`은 너무 짧거나 같은 말을 반복하는 답을 거릅니다.
- `assess_evidence_quality()`는 정답 핵심어와 검색 문서가 실제로 연결되는지 봅니다.
- `validate_generated_explanation()`은 다음을 검사합니다.
  - 정답 번호가 있는가?
  - 존재하지 않는 `[근거 N]`을 만들었는가?
  - 원문에 없던 용량·기간·비율을 추가했는가?
  - 개인에게 복용·진료를 지시하는가?

### 5. RAG 해설 생성: 344~461행

`make_explanation()`이 핵심 지휘자입니다.

```text
정답 확인 → 문제+정답으로 검색 → 검색 품질 검사
→ 근거 제한 프롬프트 → MediKo 생성 → 결과 검사 → 화면용 Markdown
```

근거가 부족하면 모델을 실행하지 않습니다. 모델이 실패해도 정답과 검색 원문은 계속 보여 줍니다.

### 6. 화면 이벤트: 464~678행

- `select_job()`은 직종 카드와 연도 선택기를 바꿉니다.
- `begin_quiz()`는 문제를 시작하고 이전 답·해설을 초기화합니다.
- `grade_answer()`는 선택 번호와 정답을 비교합니다.
- `show_explanation()`은 먼저 로딩 애니메이션을 보여 준 뒤 결과를 보냅니다.
- `gr.Blocks` 아래는 버튼·라디오·Markdown과 각 `.click()` 연결입니다.
- `demo.launch()`는 `share=False`로 외부 공개 링크를 만들지 않습니다.

## 직접 해 보는 안전한 실습

### 실습 1: 서버 설정 확인

```powershell
python -c "import app; print(app.app_server_settings())"
```

예상 결과는 `('0.0.0.0', 7860)`과 비슷합니다.

### 실습 2: 반복 출력 검사

```powershell
python -c "import app; print(app.invalid_explanation('정답 정답 정답'))"
```

`True`는 화면에 보여 주기 부적절하다는 뜻입니다.

### 실습 3: 앱 실행

```powershell
python app.py
```

브라우저에서 직종 → 연도 → 문제 → 답안 → 해설 순으로 눌러 함수 흐름을 관찰합니다.

## 주의

- `.env`의 토큰을 출력하거나 GitHub에 올리지 않습니다.
- 이 앱은 시험 학습용이며 실제 환자 판단에 사용하지 않습니다.
- 현재 GPT-Neo LoRA는 MediKo와 기반 모델이 다르므로 연결하지 않습니다.
